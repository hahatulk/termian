# 0002. Собственное хранилище Vault нативного клиента

- Статус: принято
- Дата: 2026-11-13

## Контекст

Нативный клиент читал хосты из профиля legacy-клиента (WebKit IndexedDB, записи SerializedScriptValue, поля зашифрованы `localKey` из keychain) и ничего туда не писал. Для экрана NEW HOST и правки хостов нужно место, куда записывать изменения.

Запись прямо в IndexedDB legacy-клиента потребовала бы точно воспроизвести формат WebKit и шифрование, а при одновременной работе двух клиентов грозила бы конфликтами и порчей Vault.

## Решение

У нативного клиента своё хранилище — один файл `vault.bin` в каталоге данных `termian-native` (на macOS `~/Library/Application Support/termian-native/`):

- macOS: `TMNVLT2\n`, двухбайтовая длина и обёрнутый 32-байтный ключ, 24-байтный nonce и JSON под XSalsa20-Poly1305. Ключ обёрнут через P-256 ECDH, HKDF-SHA256 и AES-GCM. Закрытый ключ Secure Enclave представлен на диске зашифрованным блоком CryptoKit; доступ к операции требует `userPresence`. Для сборки нужен Swift из Xcode или Command Line Tools.
- При первом открытии `TMNVLT1` приложение получает доступ к новому ключу через системный запрос, затем читает старый ключ `termian-native/vault-key` из Keychain. Старый ключ удаляется только после проверки, атомарной записи и сброса новой копии на диск. Отмена открытия и ошибка чтения старого ключа не заменяют файл. Старые сборки не открывают `TMNVLT2`.
- Если файла нет, приложение импортирует профиль legacy без записи в него или создаёт пустой Vault, если профиля нет. Пока Vault закрыт, приложение не читает учётные данные из него и не запускает синхронизацию.
- Формат `TMNVLT1` остаётся на других платформах с прежним системным хранилищем ключа. `TERMIAN_DEMO` использует этот формат в отдельном файле `termian-native-demo/vault.bin` с тестовым ключом без аутентификации.

## Последствия

- Правки в нативном клиенте не видны legacy-клиенту и наоборот: после первого импорта данные расходятся, пока оба клиента не подключены к одному своему облаку (портативный снимок `termius-portable-snapshot` у них общий).
- Перенос `TMNVLT2` на другой Mac не восстанавливает Vault: данные синхронизации можно получить с сервера с паролем облака; локальные данные, которых нет в снимке, так не восстанавливаются.
- Клиент расшифровывает облачный снимок в памяти и шифрует Vault перед записью. Сервер и резервные копии перед импортом используют прежний облачный формат и пароль облака. Приложение не пишет открытый Vault на диск; память работающего процесса не защищена этим форматом.
- Тесты проверяют миграцию и повторный запуск с тестовым ключом, слияние после повторного запуска и отказ Secure Enclave без системного запроса. GUI проверен с демо-данными и повреждённым тестовым файлом. Успешный вход через системный запрос Touch ID и пароля вручную не проверялся.
