# AGENTS.md — правила работы с Termian

Этот файл предназначен для ИИ-агентов, инструментов автоматизации и разработчиков, меняющих репозиторий. **Прочитайте его и относящиеся к задаче README до любых правок.** Если появится `spec.md` или локальный `AGENTS.md` в затрагиваемом каталоге, сначала прочитайте их и соблюдайте более конкретные правила. Не обходите ограничения без явного запроса пользователя.

## Код приложения

- Клиент собирается из корневого `Cargo.toml`. Логику без окна храните в библиотеке `src/lib.rs` и её модулях. `src/main.rs` содержит запуск и отрисовку.
- `src/legacy/` содержит Rust-импорт профиля снятого с выпуска клиента. Импорт читает старый профиль, но не записывает в него.
- `cloud-sync-server/` содержит самостоятельный Rust-сервер синхронизации.

## Документация

Обновляйте [README](README.md) и [спецификацию](spec.md) при изменении команд, интерфейса, форматов данных или релиза. Для сервера обновляйте [его README](cloud-sync-server/README.md). Не выдавайте настройку CI за успешный релиз.

## Сборка

```bash
cargo run --locked --bin termian-native
cargo test --locked
cargo test --locked --manifest-path scripts/release/Cargo.toml
cargo build --release --locked --bin termian-native
```

- Workflow выпускает Windows x64 и macOS Apple Silicon. Тесты и бинарник собираются одним профилем и для одного target. На macOS задавайте `MACOSX_DEPLOYMENT_TARGET=11.0`; сборка использует Swift из Xcode для системной аутентификации.
- Релиз содержит DMG, архив `.app`, портативный EXE, установщик NSIS, `latest.json` и подписи трёх пакетов автообновления. Не меняйте `assets/app/update-public-key` без ротации ключа. Для macOS без Developer ID используется ad-hoc подпись; для Developer ID требуется нотариализация и проверка Gatekeeper.
- Результаты упаковки находятся в `dist/`, кэш Cargo в `target/`. Не очищайте кэш автоматически после релиза.
- Не утверждайте, что GUI проверен, если не запускали его.

## Данные и безопасность

- Сохраняйте Vault, старые профили, каталоги `termian-data/`, включая `legacy/dist/termian-data/`, настройки облака, снимки и резервные копии.
- Не удаляйте Docker volume `sync-data` и не выполняйте `docker compose down -v` без явного запроса и подтверждённого плана восстановления.
- Не выводите в логи и не добавляйте в Git токены, пароли, приватные ключи, файлы `.env` и локальные профили.
- Синхронизация использует трёхстороннее слияние (`src/sync.rs`). Конфликты разрешает пользователь. Сохраняйте условную отправку (`If-Match`), резервную копию перед импортом и отказ от удаления локальных данных при пропавшем снимке. «Отправить» и «Получить» заменяют снимок целиком.
- Первый запуск без данных открывает пустой Vault. Повреждённое хранилище не перезаписывается пустым. Изолируйте локальные GUI-тесты от рабочего профиля.

## Перед завершением задачи

- Убедитесь, что ссылки и команды в README соответствуют реальному дереву и Cargo.
- Проверьте, что не добавлена новая копия Electron, `src-tauri/` или тяжёлые временные артефакты.
- Проверьте состояние Git; **не коммитьте, не пушьте и не переписывайте пользовательские изменения без явного запроса**.
- Укажите, какие файлы обновлены, что проверено и какие ограничения остались. Не выдавайте настройку CI за подтверждённый успешный релиз.
