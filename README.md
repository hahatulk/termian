# Termian

SSH/SFTP-клиент. Релизная версия — на **Tauri 2** (`legacy/`); в корне репозитория идёт разработка нативного клиента на Rust + GPUI без WebView ([ADR 0001](docs/adr/0001-native-gpui-client.md)). Подключения и ключи хранятся локально; при необходимости данные можно синхронизировать через собственный сервер.

## Возможности

- SSH-терминал, вкладки, ключи и пароли, Known Hosts.
- SFTP (включая локальные файлы в панели Local), проброс портов и история подключений.
- Зашифрованные логи всего вывода терминальных сессий (хранятся 60 дней, очистка за час/день/неделю/всё) с тихим резервным копированием на свой сервер ([подробнее](legacy/README.md#логи-сессий)).
- Локальный Vault для хостов, ключей и настроек.
- Синхронизация зашифрованных данных со своим сервером между несколькими устройствами: изменения объединяются как в git, конфликты решает пользователь; автосинхронизация раз в час (отключается в настройках). Сервер ограничивает подбор токена.
- Автообновление из GitHub Releases с проверкой подписи: новая версия скачивается и устанавливается в фоне, перезапуск — по кнопке ([подробнее](legacy/README.md#автообновление)).

## Быстрый старт

Нужны Node.js, npm, Rust и [системные зависимости Tauri](https://v2.tauri.app/start/prerequisites/). На Windows также требуется WebView2.

```bash
git clone https://github.com/hahatulk/termius.git
cd termius/legacy
npm ci
npm run dev
```

## Сборка

Из корня репозитория:

```bash
npm run legacy:install
npm run legacy:test
npm run legacy:check:web
npm run legacy:build:windows  # Windows x64
npm run legacy:build:mac      # macOS Apple Silicon
```

Нативный клиент (в разработке): вкладки, экран New Tab («+»: поле «Search hosts or tabs» открывает Command Palette, «Recent connections» — история подключений с путём «Personal / группа», выделение кликом и Cmd/Shift-кликом, Restore или двойной клик подключают, сессия занимает место New Tab; без истории — «Recent sessions»), Command Palette (⌘K, на Windows и Linux Ctrl+K): группы Hosts, Tabs и Quick connect (введённый `user@host[:port]` и Local Terminal), стрелки и Enter, Escape закрывает, экран Hosts (просмотр, переход по группам, поиск, NEW HOST и правка хоста в боковой панели — Address, Label, Parent Group, Tags, порт, Username, Password, сохранение по мере ввода, Connect; меню карточки по правому клику — Quick Connect, Connect with SFTP, Edit, Duplicate, Remove; группы — стрелка у NEW HOST → New Group, панель группы (Label, Parent Group без циклов), карандаш и правый клик на карточке группы (Edit, Remove; удаление группы удаляет её подгруппы и хосты после подтверждения); Enter в поиске подключает к первому найденному хосту или к введённому `user@host[:port]`), локальный терминал (кнопка TERMINAL), последовательный порт (кнопка SERIAL или Open Serial Connection): вкладка Serial с формой legacy — Serial Port (порты системы, обновляются каждые 3 секунды, первый выбирается сам), Baud rate с подсказками, Advanced (Charset, Data bits, Stop bits, Flow Control, Parity), Close и Connect (Enter); открываются только порты, которые видит система, как в legacy (`serial2`, raw-режим); DSR/DTR, как и в legacy, открывается без управления потоком; из кодировок legacy доступны те, что умеет `encoding_rs` (UTF-8, windows-125x, KOI8, ISO-8859, CP866, Shift_JIS, EUC, GBK/GB18030, Big5 и др.; CP437 и подобных нет); сессия пишется в Logs (проверено тестами и вручную: форма, подключение к системному порту без устройства, строка в Logs; обмен с настоящим устройством не проверялся) и SSH по двойному клику на хост; в терминале — выделение мышью (двойной клик выделяет слово), Cmd+C и Cmd+V, Split View: правый клик по вкладке терминала — Duplicate, «Split horizontally» (то же подключение в новой панели справа; хост, SSH-адрес или локальный терминал; Serial и логи не повторяются), Close; панели делят место по дереву legacy (`SplitViewLayoutTree`: повторный сплит делит пополам фокусную панель, закрытие отдаёт место остальным поровну); у панели заголовок с именем и крестиком, фокус переходит кликом или модификатором «Move focus between Split View panes» со стрелками (⌘⌥ на Mac); Broadcast (кнопка в заголовке окна, пока вкладка разделена, или Switch the Broadcast Mode — ⌘B на Mac) отправляет ввод и вставку из одной панели во все, вкладка получает красную точку, панели — красную рамку. Разделитель между панелями перетаскивается (панель не меньше 10% своего сплита); после закрытия панели клавиатура переходит к оставшейся. Вкладку терминала можно перетащить на панель другой вкладки — она станет панелью рядом, со стороны ближайшего к курсору края (все её панели переходят вместе с сессиями и логами); на macOS, пока курсор над вкладкой терминала, окно не перетаскивается за заголовок, чтобы двигалась вкладка. Ещё нет: вертикального списка панелей и шаблонов рабочих пространств legacy (проверено вручную на локальных терминалах: сплит, Broadcast, ⌘⌥←, перетаскивание разделителя, перетаскивание вкладки в панель справа, перемещение окна за пустой заголовок, закрытие панели; модель дерева — тестами); боковая панель терминала (Show Terminal Side-panel: ⌘S в схеме Mac, Ctrl+S в PC, или кнопка справа в заголовке на вкладке терминала): вкладка Snippets — New Snippet, поиск, пакеты раскрываются, клик показывает весь скрипт, двойной клик запускает в текущем терминале, правый клик — Run, Edit, Run in all tabs, Paste (вставить без Enter), Copy, View more; вкладка History — Shell History с PASTE и SAVE. Edit и New Snippet открывают форму на экране Snippets, а не поверх терминала, как в legacy; вкладка Theme — Font (шрифт и Text Size) и Themes (клик или ↑/↓), меняет Settings → Terminal для всех терминалов, как глобальная тема legacy (своих тем у хостов и групп в нативном клиенте нет); пока панель открыта, терминал занимает оставшуюся ширину; вкладки поиска в панели нет — поиск отдельной строкой (проверено вручную на локальном терминале: Run, Paste, History, смена темы кликом и ↓, Font); поиск «Search terminal» по сочетанию Open Terminal Search (⌘F, на Windows Ctrl+Shift+F): как в legacy, без учёта регистра и по буквальному тексту, ввод ищет снизу вверх, Enter и ▲ — предыдущее совпадение, Shift+Enter и ▼ — следующее, по кругу, найденное выделяется и прокручивается в вид, Escape закрывает (проверено тестом модели и вручную на локальном терминале). Keychain: кнопка KEY и форма ключа (Label, Passphrase для зашифрованных ключей, Private key, Public key, «Import from key file», Remove); ключ выбирается в карточке хоста (поле Key) и предлагается первым при входе. Ключи, импортированные из legacy, без приватной части и пока не используются. Identity: стрелка у KEY → New Identity (Label, Username*, Password, Key), клик по карточке открывает её; в карточке хоста поле Identity заменяет Username, Password и Key. Port Forwarding: NEW FORWARDING и форма правила (Local / Remote / Dynamic со схемой, Label, порт, Bind address, хост, адрес и порт назначения; сохранение по мере ввода), клик по карточке запускает и останавливает правило (Local — локальный порт через SSH, Dynamic — SOCKS5, Remote — порт на сервере), вопросы входа — на экране подключения; правой кнопкой — Start/Stop, Edit, Remove. Правила проброса портов и история подключений legacy-клиента импортируются из его профиля (macOS, WebKit): история — один раз при запуске, вместе с логами сессий, файлы которых копируются из `session-logs-v2` legacy (оригиналы не трогаются), повторно одни и те же подключения не добавляются, остаются 100 последних. Отметки Saved и комментарии логов legacy не переносятся. Импорт истории проверен тестами на синтетическом профиле; на настоящем профиле не запускался, потому что для этого нужен ключ legacy из Связки ключей. Logs: вывод SSH- и локальных сессий пишется в зашифрованные логи формата legacy (`TMNLOG1`, свой ключ на каждую сессию в `vault.bin`, файлы в `session-logs-v2/` каталога данных `termian-native`, хранятся 60 дней); экран Logs (Date, User, Host, Saved, сортировка по дате и по Saved) открывает запись только для чтения. Логи, как в legacy, тихо копируются в своё облако (`PUT /v1/logs/<имя>`, зашифрованы паролем шифрования облака): через 45 секунд после запуска, раз в час и через 5 секунд после конца сессии, только новые или изменившиеся файлы (`session-log-uploads.json` рядом с каталогом логов), если включена ежечасная автосинхронизация; статус синхронизации и значки в заголовке это не трогает. Если файла лога на устройстве нет, при открытии он сначала восстанавливается из облачной копии. Старый сервер без API логов — выгрузка останавливается до перезапуска, ошибка токена — пауза на час. Проверено тестами и на запущенном локально `cloud-sync-server` (отправка, восстановление, очистка). Очистка — в Settings → Account. Snippets — как в legacy: разделы Packages и Snippets (вне пакетов; двойной клик по пакету открывает его, «All snippets» возвращает), NEW SNIPPET и стрелка рядом → «New snippet package», форма сниппета (Action description до 50 символов, Package — выбор или новое имя, Script, Targets: «Add targets» / «Edit» со списком хостов и групп, поиском и флажками групп) с сохранением по мере ввода, форма пакета (Label), меню карточки Run / Edit / Duplicate / Remove, удаление пакета вместе с его сниппетами после подтверждения. Run и двойной клик запускают сниппет на сохранённых целях, а без них открывают «Select targets» (флажок «Save targets» включён по умолчанию, Run — от 1 до 100 хостов). Как в legacy, одна цель открывает вкладку, несколько — одну вкладку Split View с именем сниппета и сбалансированным расположением панелей; скрипт вводится в каждой панели, когда оболочка готова (проверено на демо-данных: вкладка «get pods» с двумя панелями). Пакеты и цели переносятся из legacy-профиля и синхронизируются через своё облако (`snippetPackages`, `targetHosts`). Shell History — панель как в legacy: команды новые сверху, клик раскрывает строку, SAVE → «Set a label» → Done/Enter делает сниппет, меню «Delete All»; команды импортируются из legacy-профиля (`history_commands`) один раз при запуске и хранятся на устройстве. Новые команды нативный клиент пока не записывает (нет интеграции с оболочкой), кнопки PASTE на экране Snippets нет и в legacy; импорт проверен тестом на синтетическом профиле. Shell Assist (генерация скрипта) не переносится. Проверено тестами моделей и вручную на демо-данных: создание пакета, перенос сниппета в пакет, Add targets с флажком группы, меню карточки, Select targets → Run (открылась SSH-вкладка), диалог удаления; ввод скрипта после входа на настоящем сервере не проверялся. Known Hosts — ключи хостов, которым доверяет нативный клиент (его файл `known_hosts` в каталоге данных `termian-native`, по нему же проверяются SSH-подключения), и записи из legacy-профиля; IMPORT, как в legacy, добавляет строки из `~/.ssh/known_hosts` (если файла нет — выбор файла), повторы не добавляются; правый клик → Remove с подтверждением «Remove known host». Проверено тестами и вручную на демо-данных (удаление, импорт). Пароли и приватные ключи при чтении профиля не расшифровываются. Вкладка SFTP: локальная панель и удалённая (выбор сохранённого хоста или `user@host`; вопросы о ключе хоста и пароле — в форме справа), навигация, сортировка, фильтр, выделение (Cmd/Ctrl и Shift), меню Actions и правый клик: копирование в другую панель, Rename, Delete, New Folder, Refresh, скрытые файлы, Select All. Копировать можно и перетаскиванием строк между панелями или файлов из Finder на удалённую панель; при совпадении имён — вопрос «File already exists» (Skip / Replace / Duplicate / Merge, Apply to All), внизу — полоса передачи и окно Transfers (Retry, Discard). Edit Permissions (права и владелец). Open / двойной клик и Open with… открывают файл в приложении; удалённый файл скачивается во временную копию, после сохранения внизу появляется строка с UPLOAD и Discard, а при отключении с несохранёнными на сервер правками — вопрос «File editing is in progress». Приложение, выбранное в Open with…, запоминается для расширения (`file-apps.json` в каталоге данных `termian-native`).

Своё облако в нативном клиенте: кнопки синхронизации, отправки и получения в заголовке окна с индикаторами состояния, как в legacy. Синхронизация — то же трёхстороннее слияние, конфликты решает только пользователь («Взять версии из облака» / «Оставить версии устройства»). Перед каждой операцией окно показывает, какие записи куда уйдут. Снимок совместим с legacy-клиентом, поэтому оба клиента могут работать с одним сервером. Форма «Своё облако» открывается кнопкой «Настроить своё облако» и сохраняет адрес, токен, пароль шифрования и Basic auth; секреты в форму не возвращаются. Ежечасная автосинхронизация отключается в этой же форме и в Settings → Account. Перед применением данных из облака создаётся зашифрованная резервная копия в `self-cloud-backups/` каталога данных `termian-native` (хранятся последние 10). Пока данные импортированы из legacy без паролей и ключей, синхронизация и отправка запрещены — сначала «Получить изменения». С живым сервером интерфейс не проверялся: проверены тесты против встроенного тестового HTTP-сервера.

Settings открываются отдельным окном через меню termian → Settings… (⌘, на macOS, Ctrl+, на Windows), как в legacy; в меню также Vaults, SFTP и Quit. Вкладки те же: **Account** — локальная учётная запись, «Своё облако» (состояние подключения, флажок автосинхронизации, «Настройки подключения», «Синхронизировать», «Получить данные с сервера», «Проверить») и очистка логов сессий «За час» / «За день» / «За неделю» / «Все» с подтверждением: удаляются подключения за период из Logs, их файлы, прочие файлы логов за период и копии в облаке (`DELETE /v1/logs?since=`); **SFTP** — приложения «Open with…» по расширениям (изменить путь, выбрать другое приложение, удалить); **Logs** — Enabled/Disabled для vault, отключение удаляет логи после подтверждения и останавливает запись (настройка остаётся на устройстве и в снимок не входит); **Version** — версия и состояние автообновления. **Terminal** — разделы legacy: переключатели (Autoreconnect, Import shell history, «Select text to copy & Right click to paste», Bell sound, Use Option as Meta key на macOS, Use bright colours for bold text), Terminal emulation type (`TERM` и тип PTY), шрифт из списка legacy или введённый системный и Text Size 4–40, все 64 темы legacy, Keyword highlighting с правилами и цветами legacy, Detect Host Operating System, Local Terminal Path (оболочки из `/etc/shells` и свои пути), Keepalive Interval, Scrollback и Post-Quantum Key Exchange (`mlkem768x25519-sha256`). Цвета, шрифт, подсветка и прокрутка меняются в открытых терминалах сразу, остальное — для новых подключений. Настройки хранятся на устройстве, как в legacy; Keepalive Interval синхронизируется через снимок (`settings.keep_alive_interval`). Как и в legacy, по умолчанию цвета берутся из темы Termius Dark (зелёный текст по умолчанию), шрифт — Source Code Pro 14, keepalive выключен. Шрифты legacy (`*.ttf`/`*.otf`) загружаются по выбору из `TERMIAN_FONTS_DIR`, `Resources/fonts` бандла, `fonts` рядом с EXE или `legacy/src/ui/assets` исходников; если файлов нет, используется Menlo. Прокрутка ограничена 100 000 строк (предел эмулятора), «0» означает максимум. Autoreconnect: если установленное SSH-подключение обрывается (канал закрылся без выхода из оболочки), вкладка переподключается сама — шесть попыток, затем пауза 30 секунд, как очередь переподключения legacy; экран и лог сессии сохраняются, а если сервер просит пароль или подтверждение ключа, показывается экран подключения. Detect OS: для сохранённого хоста без ОС после входа система определяется по строке версии сервера, а если её там нет — скриптом legacy в отдельном exec-канале (по `$SHELL`: обычный, fish или RouterOS), и записывается в хост. Autocomplete пока не перенесён (показан как Disabled), Import shell history сохраняется, но импорт истории ещё не перенесён; кнопка «Let us know» не перенесена. **Shortcuts** — схемы legacy: «Mac hotkeys» (на macOS) и «PC hotkeys» с теми же сочетаниями, «Disabled», свои схемы. Щелчок по строке записывает новое сочетание (Enter — сохранить, Backspace — отключить действие, Escape — отмена; для переключения вкладок [1…9] и панелей — только модификаторы), занятое сочетание снимается с другого действия с предупреждением. Изменение встроенной схемы создаёт «<имя> copy»; свою схему можно переименовать и удалить с подтверждением. Сочетания действуют в главном окне сразу. Хранится на устройстве, как в legacy. Действия, которых в нативном клиенте ещё нет , назначаются, но пока ничего не делают; Jump To открывает Command Palette. Проверено на демо-данных: запись ⌘⇧H для Open Hosts Page, создание копии схемы, ⌘2, ⌘⇧H, ⌘P, ⌘T, ⌘W в главном окне, удаление схемы. Проверено тестами моделей (тексты состояний, очистка логов, удаление логов в облаке на тестовом сервере, ассоциации) и вручную на демо-данных (`TERMIAN_DEMO=1`): открытие Settings из меню, все вкладки, смена темы, шрифта и размера в открытом терминале, форма «Своё облако» из Account. С живым сервером синхронизации и на Windows не проверялось.

Автообновление нативного клиента читает тот же `latest.json` релиза и принимает только пакеты, подписанные ключом из `plugins.updater.pubkey` legacy-клиента и привязанные к объявленной версии (`version:` в подписи). Проверка идёт через 20 секунд после запуска и затем каждые 6 часов; найденный пакет скачивается и встаёт на место `.app` (macOS, `darwin-aarch64`) или портативного EXE (Windows, `windows-x86_64`), а уведомление «Termian … установлен» предлагает «Перезапустить» или «Позже». Работает только в сборках с `TERMIAN_RELEASE_VERSION`; локальная сборка не обновляется, `TERMIAN_DISABLE_UPDATES` отключает проверку. Релизов нативного клиента пока нет, поэтому установка из настоящего релиза не проверялась: проверены тесты подписи (настоящая подпись ключа выпуска), разбора `latest.json` и замены бандла. В отличие от legacy, бандл без прав на запись не обновляется (legacy запрашивает пароль администратора). Прогресс загрузки, «Проверить обновления» и «Перезапустить и обновить» — в Settings → Version.

```bash
npm test                 # cargo test
npm run dev              # cargo run: хосты из профиля legacy-клиента (macOS, нужен доступ к Связке ключей)
TERMIAN_DEMO=1 cargo run # тестовые данные без профиля и Связки ключей
```

SSH в нативном клиенте: при подключении вкладка показывает экран подключения, как в legacy-клиенте (шаги, отпечаток ключа, «Close / Continue / Add and continue», запрос пароля, «Show logs», «Retry»); тот же экран используется для SFTP. Ключи хостов хранятся в собственном `known_hosts` (`~/Library/Application Support/termian-native/known_hosts` на macOS): «Continue» доверяет ключу только на эту сессию, «Add and continue» сохраняет его; сменившийся ключ блокирует подключение. Аутентификация: ключи `~/.ssh/id_ed25519`, `id_ecdsa`, `id_rsa`, затем пароль или keyboard-interactive. Пароли и ключи из Vault legacy-клиента пока не используются; пароль, сохранённый в карточке хоста нативного клиента, пробуется перед вопросом о пароле.

Данные нативного клиента хранятся отдельно от legacy-клиента: зашифрованный `vault.bin` в каталоге данных `termian-native`, ключ — в системном хранилище секретов (служба `termian-native`). При первом запуске хосты один раз импортируются из профиля legacy; профиль legacy не меняется, и дальше данные двух клиентов связывает только своё облако ([ADR 0002](docs/adr/0002-native-vault-storage.md)). С `TERMIAN_DEMO=1` используется отдельный демо-файл во временном каталоге без обращения к keychain.

Профиль legacy-клиента читается только на чтение: базы IndexedDB копируются во временный каталог. Пока поддерживается только профиль WebKit на macOS; профиль WebView2 на Windows (LevelDB) не читается.

Потребление памяти можно сравнить скриптом `scripts/measure-rss.sh <имя процесса>`. На macOS WebView работает в отдельных процессах `com.apple.WebKit.*`, их нужно учитывать отдельно.

| Платформа | Формат | Статус |
| --- | --- | --- |
| Windows x64 | Portable EXE | Локальная сборка и запуск проверены |
| Windows x64 | Установщик NSIS (`-setup.exe`, для текущего пользователя) | Собирается в CI, запуск не проверен |
| macOS Apple Silicon | DMG | CI настроен, запуск на Mac не подтверждён |

Результаты сборки находятся в `legacy/dist/`. **Не удаляйте `legacy/dist/termian-data/`** — там хранится пользовательский профиль портативной версии. Установленная версия хранит профиль в `%APPDATA%` / `%LOCALAPPDATA%` (`app.termian.desktop`).
