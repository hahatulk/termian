# Termian

Нативный SSH/SFTP-клиент на Rust и GPUI ([ADR 0001](docs/adr/0001-native-gpui-client.md)). Подключения и ключи хранятся локально; при необходимости данные можно синхронизировать через собственный сервер.

## Возможности

- SSH-терминал, вкладки, ключи и пароли, Known Hosts.
- SFTP (включая локальные файлы в панели Local), проброс портов и история подключений.
- Зашифрованные логи всего вывода терминальных сессий (хранятся 60 дней, очистка за час/день/неделю/всё) с синхронизацией через своё облако ([подробнее](spec.md#44-логи-сессий)).
- Локальный Vault для хостов, ключей и настроек.
- Синхронизация зашифрованных данных со своим сервером между несколькими устройствами: трёхстороннее слияние автоматически разрешает конфликты; автосинхронизация раз в час (отключается в настройках). Сервер ограничивает подбор токена.
- Автообновление из GitHub Releases с проверкой подписи: новая версия скачивается и устанавливается в фоне, перезапуск — по кнопке ([подробнее](spec.md#46-автообновление)).

## Быстрый старт

Нужен Rust stable с Cargo. На macOS установите Xcode или Command Line Tools, на Windows установите Visual Studio Build Tools с компонентами C++ и Windows SDK.

```bash
git clone https://github.com/hahatulk/termian.git
cd termian
cargo run --locked --bin termian-native
```

На macOS команда `TERMIAN_DEMO=1 cargo run --locked --bin termian-native` запускает приложение с тестовым профилем.

В текстовых полях `Ctrl` и `Cmd` с `A`, `C`, `X` и `V` выделяют весь текст, копируют, вырезают и вставляют. Правый клик открывает меню редактирования. В поля паролей можно вставлять текст; копирование и вырезание отключены.

## Сборка

```bash
cargo test --locked
cargo build --locked --release --bin termian-native
```

[Workflow релиза](.github/workflows/release.yml) собирает Windows x64 и macOS Apple Silicon через Cargo. Упаковка Windows использует NSIS, macOS использует `hdiutil` и `codesign`. Пакеты выкладываются в `dist/` на раннерах. [Форматы и секреты релиза](spec.md#94-релиз).

Панель инструментов Vaults, как в legacy: справа поиск (лупа открывает поле фильтра по имени; на Hosts — своя строка поиска), меню вида «Grid / List» и сортировки «A-z», «Z-a», «Newest to oldest» (по умолчанию), «Oldest to newest» — на каждом разделе отдельно, хранятся на устройстве; у Hosts ещё фильтр по тегам («Search tags», выбор нескольких тегов, «Clear selection»; хост показывается, если у него есть хотя бы один выбранный тег — совпадение с legacy не проверено). Меню панели открываются под своими кнопками. У записей нет даты создания, поэтому «новее/старше» определяется по порядку добавления (id). NEW FORWARDING — разделённая кнопка: сама кнопка открывает Port Forwarding Wizard, как в legacy (тип → порт и адрес привязки → хост → назначение → метка; у Remote сначала хост, у Dynamic без назначения; Back, «Skip wizard» переходит к форме, правило сохраняется только по Done), а меню Local / Remote / Dynamic Forwarding — сразу форму; в форме нового правила есть ссылка «Open Port Forwarding Wizard». Шаги мастера проверены тестами, вид в GUI ещё не сверялся с legacy. У Logs нет панели инструментов, строки — карточки, пустой комментарий показывает «Add a comment» только при наведении. Иконки вкладки Vaults и стрелок выпадающих списков взяты из legacy. Проверено на демо-данных сравнением снимков с legacy-клиентом.

Анимации и поведение, как в legacy: после входа экран подключения заполняет полосу зелёным (0,3 с) и растворяется поверх терминала; слайдеры редакторов (хост, группа, ключ, identity, правило, сниппет, пакет, Shell History) выезжают справа за 0,2 с и сдвигают карточки, сетка подбирает число колонок по ширине (карточка не уже ~220 px); новый хост показывается первой карточкой «Enter IP or Hostname...» с зелёной рамкой; сортировка Hosts «Newest to oldest» ставит первыми хосты по последнему подключению (как `hostInteractions`), последний подключённый хост обведён зелёным. Анимацию подключения на настоящем сервере не проверял; слайд и сетка проверены на демо-данных.

Форма хоста, как в legacy: в General — Backspace (Default / Ctrl+H, отправляет ^H вместо DEL); в SSH после учётных данных — Agent Forwarding (Enabled/Disabled: запрос `auth-agent-req@openssh.com` и пересылка каналов агента в локальный `SSH_AUTH_SOCK`; на Windows не поддерживается), Startup Command (сниппет выполняется после входа, если хост не открыт запуском другого сниппета), Environment Variable (отдельная панель с парами имя/значение, отправляются до запуска оболочки; сервер может отклонить по AcceptEnv), кодировка (список как у Serial; вывод и ввод перекодируются) и тема терминала хоста (панель «Select Color Theme» с превью, «Default» — глобальная тема). Поля хранятся в формате снимка legacy (`backspace` у хоста; `agent_forwarding`, `charset`, `env_variables`, `startup_snippet`, `color_scheme` в `ssh_config`) и читаются из профиля legacy. Закрытие новой формы, где что-то заполнено, но нет адреса, спрашивает «Do you want to discard changes?». Модель, снимок и параметры SSH проверены тестами, форма — на демо-данных; Agent Forwarding, переменные и кодировка на настоящем сервере и диалог отмены в GUI не проверялись. Блок SSH, как в legacy: «SSH on [22] port», затем «Credentials» — Username с подсказкой сохранённых identity при фокусе (выбранная identity заменяет логин, пароль и ключ, × снимает её), Password и «+ SSH.id, Key, Certificate, FIDO2»: меню с Key (поле Key со списком ключей) и Certificate (только ключи с сертификатом; у выбранного ключа вместо типа показано «Certificate»); SSH.id — облачный сервис, FIDO2 здесь не поддерживается, оба показаны неактивными. SSH-сертификаты, как в legacy, принадлежат ключу: в форме ключа Keychain есть поле Certificate (OpenSSH user certificate, неверный текст — «Unknown certificate format»); при входе сначала предлагается сертификат, затем сам ключ. Сертификаты читаются из хранилища `ssh_certificates` профиля legacy и из снимка синхронизации (`sshKeys[].certificates`, сохраняется `local_id`). Вход по сертификату проверен тестом с тестовым SSH-сервером, на настоящем сервере и в GUI не проверялся. **Export to host** в форме сохранённого ключа открывает слайдер «Key Export», как в legacy: «Export to» (хост), «Location – $1» (`~/.ssh`), «Filename – $2» (`authorized_keys`), подсказка о поддержке только UNIX и Advanced со скриптом legacy; «Export and Attach» входит на хост через экран подключения, выполняет скрипт (успех — код 0, иначе показывается вывод скрипта), показывает «Exported» и назначает ключ хосту (или его identity). Сохранённый публичный ключ проверяется как OpenSSH-ключ. Скрипт получает каталог, имя файла и текст записи как аргументы `$1`, `$2` и `$3`. В пользовательском скрипте заключайте `"$1"`, `"$2"` и `"$3"` в кавычки. Экспорт multikey и «Save authorized_keys file» не перенесены. Подстановка и выполнение скрипта проверены тестами с тестовым SSH-сервером, GUI и настоящий сервер не проверялись. Вкладка лога называется «Log: <хост>, ЧЧ:ММ:СС <дата>», как в legacy. Слайдеры закрываются кнопкой «→|», как в legacy; под заголовком формы хоста — «Personal vault» (других хранилищ в этом клиенте нет). Не переносятся: Proxy и Host Chaining (функции Termius Pro) и Telnet (legacy-клиент тоже не подключается по Telnet).

Интерфейс клиента: вкладки, экран New Tab («+»: поле «Search hosts or tabs» открывает Command Palette, «Recent connections» — история подключений с путём «Personal / группа», выделение кликом и Cmd/Shift-кликом, Restore или двойной клик подключают, сессия занимает место New Tab; без истории — «Recent sessions»), Command Palette (⌘K, на Windows и Linux Ctrl+K): группы Hosts, Tabs и Quick connect (введённый `user@host[:port]` и Local Terminal), стрелки и Enter, Escape закрывает, экран Hosts (просмотр, переход по группам, поиск, NEW HOST и правка хоста в боковой панели — Address, Label, Parent Group, Tags, порт, Username, Password, сохранение по мере ввода, Connect; меню карточки по правому клику — Quick Connect, Connect with SFTP, Edit, Duplicate, Remove; группы — стрелка у NEW HOST → New Group, панель группы (Label, Parent Group без циклов), карандаш и правый клик на карточке группы (Edit, Remove; удаление группы удаляет её подгруппы и хосты после подтверждения); Enter в поиске подключает к первому найденному хосту или к введённому `user@host[:port]`), локальный терминал (кнопка TERMINAL), последовательный порт (кнопка SERIAL или Open Serial Connection): вкладка Serial с формой legacy — Serial Port (порты системы, обновляются каждые 3 секунды, первый выбирается сам), Baud rate с подсказками, Advanced (Charset, Data bits, Stop bits, Flow Control, Parity), Close и Connect (Enter); открываются только порты, которые видит система, как в legacy (`serial2`, raw-режим); DSR/DTR, как и в legacy, открывается без управления потоком; из кодировок legacy доступны те, что умеет `encoding_rs` (UTF-8, windows-125x, KOI8, ISO-8859, CP866, Shift_JIS, EUC, GBK/GB18030, Big5 и др.; CP437 и подобных нет); сессия пишется в Logs (проверено тестами и вручную: форма, подключение к системному порту без устройства, строка в Logs; обмен с настоящим устройством не проверялся) и SSH по двойному клику на хост; после входа строка установки интеграции с оболочкой не мелькает: пока она выполняется, терминал показывает предыдущий кадр; в терминале — выделение мышью (двойной клик выделяет слово), Cmd+C и Cmd+V, Split View: правый клик по вкладке терминала — Duplicate, «Split horizontally» (то же подключение в новой панели справа; хост, SSH-адрес или локальный терминал; Serial и логи не повторяются), Close; панели делят место по дереву legacy (`SplitViewLayoutTree`: повторный сплит делит пополам фокусную панель, закрытие отдаёт место остальным поровну); у панели заголовок с именем и крестиком, фокус переходит кликом или модификатором «Move focus between Split View panes» со стрелками (⌘⌥ на Mac); Broadcast (кнопка в заголовке окна, пока вкладка разделена, или Switch the Broadcast Mode — ⌘B на Mac) отправляет ввод и вставку из одной панели во все, вкладка получает красную точку, панели — красную рамку. Разделитель между панелями перетаскивается (панель не меньше 10% своего сплита); после закрытия панели клавиатура переходит к оставшейся. Вкладку терминала можно перетащить на панель другой вкладки — она станет панелью рядом, со стороны ближайшего к курсору края (все её панели переходят вместе с сессиями и логами); на macOS, пока курсор над вкладкой терминала, окно не перетаскивается за заголовок, чтобы двигалась вкладка. Шаблоны рабочих областей legacy: на выбранной вкладке с несколькими панелями точка «Save template» (имя по умолчанию «New Workspace Template») или «Update template», если вкладка отличается от шаблона (подключения, порядок, раскладка, вид, имя). На New Tab раздел «Workspace templates» над «Recent connections»: клик выбирает, двойной клик или Enter открывает подключения шаблона с его раскладкой, заголовками и видом; при наведении «N connections» сменяется кнопками переименования и удаления; переименование на месте (Enter — сохранить, Escape — отменить). «Create a workspace» сохраняет выбранные недавние подключения как безымянный шаблон и сразу открывает переименование. В меню хоста — «Add to Workspace: <вкладка>». Focus View: слева список «Terminals • N» с кнопками Split view и Broadcast input, показан один терминал; кнопка «Focus mode» в заголовке панели Split View переключает в Focus View (иконки и подсказки — из legacy). Шаблоны хранятся в форме снимка legacy (`workspaceTemplates`) и синхронизируются с полями, которые этот клиент не использует; в шаблон попадают только сохранённые хосты и локальные терминалы. При открытии шаблона его startup-сниппет выполняется, как в legacy: переход в `startupDirectory` (`cd`, `~/` раскрывается), затем `startupScript` (или `script` сниппета) одной строкой — для SSH после входа и интеграции с оболочкой, для локального терминала после строки интеграции или сразу, если интеграция выключена; проверено тестами построения команды, выполнение в GUI не проверялось; шаблоны из профиля legacy (IndexedDB `workspace_templates`, зашифрованные имя и терминалы) импортируются один раз при запуске: шаблон с уже занятым id (пришедший синхронизацией) пропускается, терминалы удалённых хостов отбрасываются, шаблон без терминалов не добавляется; проверено тестами на синтетическом профиле, с настоящим профилем не проверялось. Модель проверена тестами; GUI не проверялся. (Split View проверен вручную на локальных терминалах: сплит, Broadcast, ⌘⌥←, перетаскивание разделителя, перетаскивание вкладки в панель справа, перемещение окна за пустой заголовок, закрытие панели; модель дерева — тестами); боковая панель терминала (Show Terminal Side-panel: ⌘S в схеме Mac, Ctrl+S в PC, или кнопка справа в заголовке на вкладке терминала): вкладки — маленькие иконки слева, как в legacy; первая — Terminal: «Search terminal - ⌘ + F» открывает поиск по терминалу, ↑/↓ — предыдущее/следующее совпадение, и Autocomplete (Enabled/Disabled, общая настройка с Settings → Terminal); вкладка Snippets — New Snippet, поиск, пакеты раскрываются, клик показывает весь скрипт, двойной клик запускает в текущем терминале, правый клик — Run, Edit, Run in all tabs, Paste (вставить без Enter), Copy, View more; вкладка History — Shell History с PASTE и SAVE. Edit и New Snippet открывают форму на экране Snippets, а не поверх терминала, как в legacy; вкладка Theme — «Font ›» (шрифт и Text Size) и Themes (клик или ↑/↓; превью строками в цветах темы и число пользователей из таблицы legacy, «new» для новых), меняет глобальную тему Settings → Terminal, как в legacy; на вкладке терминала полоса вкладок, вкладки и боковая панель окрашиваются от фона темы терминала, как в legacy; неактивные вкладки показывают значок вида (New Tab — квадрат с «+»), крестик закрытия — только у активной; пока панель открыта, терминал занимает оставшуюся ширину; вкладки поиска в панели нет — поиск отдельной строкой (проверено вручную на локальном терминале: Run, Paste, History, смена темы кликом и ↓, Font); поиск «Search terminal» по сочетанию Open Terminal Search (⌘F, на Windows Ctrl+Shift+F): как в legacy, без учёта регистра и по буквальному тексту, ввод ищет снизу вверх, Enter и ▲ — предыдущее совпадение, Shift+Enter и ▼ — следующее, по кругу, найденное выделяется и прокручивается в вид, Escape закрывает (проверено тестом модели и вручную на локальном терминале). Keychain: кнопка KEY и форма ключа (Label, Passphrase для зашифрованных ключей, Private key, Public key, «Import from key file», Remove); ключ выбирается в карточке хоста (поле Key) и предлагается первым при входе. Генерация — стрелка у KEY → Generate Key или кнопка Generate Key в новой форме: ED25519 (по умолчанию), ECDSA (521/384/256) и RSA (4096/2048/1024; 1024, как и в backend legacy, отклоняется с ошибкой), Label, Passphrase, Save passphrase, Generate & save. Пара генерируется в фоне в формате OpenSSH с комментарием `Generated By Termian` и сохраняется в зашифрованный Vault; без Save passphrase парольная фраза не сохраняется, SSH запрашивает её при входе. Закрытая форма не сохраняет поздний результат генерации. В отличие от legacy, генерация открывается отдельной формой, а не вкладкой Paste / Import / Generate; Cipher и Rounds пока не настраиваются — используются значения OpenSSH-библиотеки (backend legacy также не передаёт эти параметры). Генерация, шифрование, типы и запрос парольной фразы проверены тестами; GUI не проверялся. Ключи из legacy импортируются с приватной частью и парольной фразой. Identity: стрелка у KEY → New Identity (Label, Username*, Password, Key), клик по карточке открывает её; в карточке хоста поле Identity заменяет Username, Password и Key. Port Forwarding: NEW FORWARDING и форма правила (Local / Remote / Dynamic со схемой, Label, порт, Bind address, хост, адрес и порт назначения; сохранение по мере ввода), клик по карточке запускает и останавливает правило (Local — локальный порт через SSH, Dynamic — SOCKS5, Remote — порт на сервере), вопросы входа — на экране подключения; правой кнопкой — Start/Stop, Edit, Remove. Правила проброса портов и история подключений legacy-клиента импортируются из его профиля (macOS, WebKit): история — один раз при запуске, вместе с логами сессий, файлы которых копируются из `session-logs-v2` legacy (оригиналы не трогаются), повторно одни и те же подключения не добавляются, остаются 100 последних. Отметки Saved и комментарии legacy (таблица `bookmarks`; связь через `history_local_id` или `log_id` → `logSet`) переносятся вместе с историей; для истории, импортированной раньше, они добавляются один раз при запуске (совпадение по времени начала и имени, уже написанный здесь комментарий сохраняется). Комментарий обрезается до 2000 единиц UTF-16. Проверено тестами на синтетическом профиле, с настоящим профилем не проверялось. Импорт истории проверен тестами на синтетическом профиле; на настоящем профиле не запускался, потому что для этого нужен ключ legacy из Связки ключей. Logs: вывод SSH- и локальных сессий пишется в зашифрованные логи формата legacy (`TMNLOG1`, свой ключ на каждую сессию в `vault.bin`, файлы в `session-logs-v2/` каталога данных `termian-native`, хранятся 60 дней); экран Logs (Date, User, Host, Saved, сортировка по дате и по Saved) открывает запись только для чтения. Логи, как в legacy, тихо копируются в своё облако (`PUT /v1/logs/<имя>`, зашифрованы паролем шифрования облака): через 45 секунд после запуска, раз в час и через 5 секунд после конца сессии, только новые или изменившиеся файлы (`session-log-uploads.json` рядом с каталогом логов), если включена ежечасная автосинхронизация; статус синхронизации и значки в заголовке это не трогает. Если файла лога на устройстве нет, при открытии он сначала восстанавливается из облачной копии. Старый сервер без API логов — выгрузка останавливается до перезапуска, ошибка токена — пауза на час. Проверено тестами и на запущенном локально `cloud-sync-server` (отправка, восстановление, очистка). Очистка — в Settings → Account. Snippets — как в legacy: разделы Packages и Snippets (вне пакетов; двойной клик по пакету открывает его, «All snippets» возвращает), NEW SNIPPET и стрелка рядом → «New snippet package», форма сниппета (Action description до 50 символов, Package — выбор или новое имя, Script, Targets: «Add targets» / «Edit» со списком хостов и групп, поиском и флажками групп) с сохранением по мере ввода, форма пакета (Label), меню карточки Run / Edit / Duplicate / Remove, удаление пакета вместе с его сниппетами после подтверждения. Run и двойной клик запускают сниппет на сохранённых целях, а без них открывают «Select targets» (флажок «Save targets» включён по умолчанию, Run — от 1 до 100 хостов). Как в legacy, одна цель открывает вкладку, несколько — одну вкладку Split View с именем сниппета и сбалансированным расположением панелей; скрипт вводится в каждой панели, когда оболочка готова (проверено на демо-данных: вкладка «get pods» с двумя панелями). Пакеты и цели переносятся из legacy-профиля и синхронизируются через своё облако (`snippetPackages`, `targetHosts`). Shell History — панель как в legacy: команды новые сверху, клик раскрывает строку, SAVE → «Set a label» → Done/Enter делает сниппет, меню «Delete All»; команды импортируются из legacy-профиля (`history_commands`) один раз при запуске и хранятся на устройстве. Новые команды записывает интеграция с оболочкой (Settings → Terminal → «Shell integration (record commands)», включена по умолчанию): как в legacy, в новую оболочку — локальную или SSH, и после переподключения — за альтернативным экраном вводится строка установки, когда вывод затихнет (баннер входа остаётся виден), а хуки сообщают о командах последовательностями legacy `OSC 4545` (`CommandStarted`, `CommandExited`, `SetCwd`, границы приглашения). Для bash используется скрипт legacy, для zsh и fish — свои хуки с теми же событиями; скрипты сжаты (gzip + base64), строка около 2,7 КБ; для других оболочек строка ничего не делает, а экран в любом случае возвращается (через 4 секунды — сам терминал). Сниппет запуска вводится после строки установки. Команда попадает в Shell History после завершения, с хостом; повтор поднимается наверх, хранятся 2000 последних. Вкладка History боковой панели показывает историю хоста фокусной панели (для локальных и несохранённых — всю). Проверено тестами на настоящих bash 3.2, zsh 5.9 и fish 4.9 этой машины и вручную в локальном терминале с конфигурацией пользователя; на удалённом сервере по SSH не проверялось. Кнопки PASTE на экране Snippets нет и в legacy; импорт проверен тестом на синтетическом профиле. Shell Assist (генерация скрипта) не переносится. Проверено тестами моделей и вручную на демо-данных: создание пакета, перенос сниппета в пакет, Add targets с флажком группы, меню карточки, Select targets → Run (открылась SSH-вкладка), диалог удаления; ввод скрипта после входа на настоящем сервере не проверялся. Known Hosts — ключи хостов, которым доверяет нативный клиент (его файл `known_hosts` в каталоге данных `termian-native`, по нему же проверяются SSH-подключения), и записи из legacy-профиля; IMPORT, как в legacy, добавляет строки из `~/.ssh/known_hosts` (если файла нет — выбор файла), повторы не добавляются; правый клик → Remove с подтверждением «Remove known host». Проверено тестами и вручную на демо-данных (удаление, импорт). Пароли и приватные ключи при чтении профиля не расшифровываются. Вкладка SFTP: две панели, каждая — локальный диск или хост со своим подключением (выбор сохранённого хоста или `user@host`; вопросы о ключе хоста и пароле — в форме панели). Слева по умолчанию диск, справа — «Connect to host»; кнопка DISCONNECT рядом с «Local» (как в legacy) на любой панели открывает выбор хоста, как в legacy: «Select Host» / Vaults со стрелкой назад, зелёная кнопка Local (панель показывает диск), поиск, затем Groups (группа открывается на месте, путь «All hosts › …») и Hosts открытой группы; при поиске — найденные хосты. Копирование между двумя панелями-дисками недоступно. У подключённой панели — кнопка DISCONNECT (и Close в меню Actions; левая возвращается к диску, правая — к «Connect to host»), на экране подключения — Close. Копирование: диск → хост (загрузка), хост → диск (скачивание) и хост → хост: файлы скачиваются с первого хоста во временную папку и загружаются на второй, временная копия удаляется; вопрос «File already exists» — по папке назначения, перетаскивание из Finder — на любую панель-хост; передачи привязаны к своему подключению, отключение одной панели не трогает передачи другой. Проверено: тест «хост → временная папка → хост» на двух SFTP-серверах (файл и вложенная папка), вручную на демо-данных — выбор хоста слева, одновременные подключения в двух панелях, Close слева; копирование между двумя настоящими хостами в интерфейсе не проверялось, навигация, сортировка, фильтр, выделение (Cmd/Ctrl и Shift), меню Actions и правый клик: копирование в другую панель, Rename, Delete, New Folder, Refresh, скрытые файлы, Select All. Копировать можно и перетаскиванием строк между панелями или файлов из Finder на удалённую панель; при совпадении имён — вопрос «File already exists» (Skip / Replace / Duplicate / Merge, Apply to All), внизу — полоса передачи и окно Transfers (Retry, Discard). Edit Permissions (права и владелец). Open / двойной клик и Open with… открывают файл в приложении; удалённый файл скачивается во временную копию, после сохранения внизу появляется строка с UPLOAD и Discard, а при отключении с несохранёнными на сервер правками — вопрос «File editing is in progress». Приложение, выбранное в Open with…, запоминается для расширения (`file-apps.json` в каталоге данных `termian-native`).

В Vaults → Logs записи собраны по дням. Столбцы User, Action, Host, Time, Device и Location показывают метаданные записи. Клиент не собирает геолокацию; в Location показано "Location unavailable". Имя компьютера сохраняется для новых записей.

Ручная и ежечасная синхронизация отправляют завершённые логи и добавляют записи с других устройств. Нажмите на запись, чтобы скачать и открыть зашифрованную копию. Для логов, отправленных старой версией, выполните синхронизацию с устройства, где осталась исходная запись и файл.

При открытии незавершённого журнала клиент показывает доступный вывод и предупреждение. Для новых завершённых журналов клиент проверяет порядок и полноту блоков. Предыдущий Rust-клиент читает эти файлы без проверки последовательности. Для файла нулевой длины текущий клиент показывает предупреждение.

**Комментарии в Logs:** закладка в столбце Location открывает редактор комментария; Enter или клик снаружи сохраняет, Shift+Enter добавляет строку, Escape отменяет. Сохранение текста ставит закладку; пустая закладка тоже допустима, снятие закладки удаляет комментарий. В строке видны первые две строки, целиком — при редактировании; ссылки HTTP(S) открываются по клику. Предел — 2000 единиц UTF-16, как в legacy, без разрыва Unicode-символа. Комментарии и закладки синхронизируются в зашифрованном снимке вместе с записью лога. Старый Vault без комментариев читается. Saved сохраняет запись истории сверх обычного лимита, но не отменяет 60-дневную ретенцию файлов. Проверено тестами хранения/редактирования и в демо-окне macOS: Unicode-вставка, выделение, несколько строк, Enter, Escape, сохранение кликом снаружи, снятие закладки, сортировка Saved и сохранность после перезапуска. Windows, IME и открытие ссылки в браузере не проверялись.

При ручном **Retry** после ошибки SFTP-передачи начатый этой передачей файл продолжается с уже записанного места, если размер исходного файла не изменился и частичная копия совпадает с его началом; иначе показывается ошибка. При Replace клиент копирует файл или папку во временный каталог и заменяет назначение после полной передачи. Если файл пропущен, клиент не публикует неполную копию. Если имя назначения занято к моменту завершения передачи, создание отменяется. Слияние папок и замена требуют явного выбора. В Windows команда "Открыть" передаёт путь системному обработчику файлов. При загрузке папки на сервер клиент пропускает локальные ссылки. Передача останавливается до записи байтов сверх объявленного размера и не переносит биты setuid, setgid и sticky. Проверка частичной копии перечитывает её целиком и требует права чтения; автоматические повторы и переподключение не перенесены. Изменение исходного файла за пределами уже скопированной части при прежнем размере не обнаруживается. Проверено тестами локальных файлов и продолжения загрузки и скачивания через тестовый SFTP-сервер; Retry в GUI не проверялся.

Своё облако в нативном клиенте: в заголовке окна есть кнопка синхронизации с индикатором состояния. Для принудительной отправки клиент должен открыть существующий снимок текущим паролем. Если снимок изменился во время отправки, сервер отклоняет запись. Принудительная отправка и получение доступны в Settings → Account → «Своё облако» и требуют подтверждения замены снимка. При конфликте двух изменений синхронизация сохраняет версию из облака. Если одна сторона удалила запись, а другая изменила, сохраняется изменённая версия. Перед каждой операцией окно показывает, какие записи куда уйдут. Снимок совместим с legacy-клиентом, поэтому оба клиента могут работать с одним сервером. Пароль существующего снимка можно ввести без ограничений по длине, в том числе оставить пустым при первом подключении. Однострочные поля показывают длинные значения в своих границах и прокручивают их до курсора. Форма «Своё облако» открывается кнопкой «Настроить своё облако» и сохраняет адрес, токен, пароль шифрования и Basic auth; секреты в форму не возвращаются. Ежечасная автосинхронизация отключается в этой же форме и в Settings → Account. Перед применением данных из облака создаётся резервная копия Vault в `self-cloud-backups/device/` рядом с текущим `vault.bin`. Последние 10 файлов `.bin` зашифрованы локальным ключом Vault. Старые копии `.json` остаются в исходном каталоге и используют прежний пароль облака, в том числе пустой. Деморежим хранит копии рядом с демо-Vault. Пока данные импортированы из legacy без паролей и ключей, синхронизация и отправка запрещены — сначала «Получить изменения». С живым сервером интерфейс не проверялся: проверены тесты против встроенного тестового HTTP-сервера.

Настройки открываются через кнопку `⋯` в шапке → Settings… (`⌘,` на macOS, `Ctrl+,` на Windows). В том же меню есть Vaults, SFTP, «Доступ к файлам…» (только macOS) и Quit Termian. «Доступ к файлам», как в legacy, — отдельное окно со статусом Домашней папки, Рабочего стола, Документов, Загрузок и (необязательно) Полного доступа к диску; статус обновляется раз в 2 секунды, у папки без доступа — «Открыть настройки» (раздел «Файлы и папки» или «Полный доступ к диску» в Системных настройках). Модель проверена тестом; окно в GUI и запрос прав macOS не проверялись. Вкладки те же: **Account** — локальная учётная запись, «Своё облако» (состояние подключения, флажок автосинхронизации, «Настройки подключения», «Синхронизировать», «Получить данные с сервера», «Проверить») и очистка логов сессий «За час» / «За день» / «За неделю» / «Все» с подтверждением: удаляются подключения за период из Logs, их файлы, прочие файлы логов за период и копии в облаке (`DELETE /v1/logs?since=`); **SFTP** — приложения «Open with…» по расширениям (изменить путь, выбрать другое приложение, удалить); **Logs** — Enabled/Disabled для vault, отключение удаляет логи после подтверждения и останавливает запись (настройка остаётся на устройстве и в снимок не входит); **Version** — версия и состояние автообновления. **Terminal** — разделы legacy: переключатели (Autoreconnect, Import shell history, «Select text to copy & Right click to paste», Bell sound, Use Option as Meta key на macOS, Use bright colours for bold text), Terminal emulation type (`TERM` и тип PTY), шрифт из списка legacy или введённый системный и Text Size 4–40, все 64 темы legacy, Keyword highlighting с правилами и цветами legacy, Detect Host Operating System, Local Terminal Path (оболочки из `/etc/shells` и свои пути), Keepalive Interval, Scrollback и Post-Quantum Key Exchange (`mlkem768x25519-sha256`). Цвета, шрифт, подсветка и прокрутка меняются в открытых терминалах сразу, остальное — для новых подключений. Настройки хранятся на устройстве, как в legacy; Keepalive Interval синхронизируется через снимок (`settings.keep_alive_interval`). Как и в legacy, по умолчанию цвета берутся из темы Termius Dark (зелёный текст по умолчанию), шрифт — Source Code Pro 14, keepalive выключен. Шрифты терминала встроены в бинарник. Одноимённые файлы из `TERMIAN_FONTS_DIR`, `Resources/fonts` или `fonts` рядом с EXE имеют приоритет. Прокрутка ограничена 100 000 строк (предел эмулятора), «0» означает максимум. Autoreconnect: если установленное SSH-подключение обрывается (канал закрылся без выхода из оболочки), вкладка переподключается сама — шесть попыток, затем пауза 30 секунд, как очередь переподключения legacy; экран и лог сессии сохраняются, а если сервер просит пароль или подтверждение ключа, показывается экран подключения. Detect OS: для сохранённого хоста без ОС после входа система определяется по строке версии сервера, а если её там нет — скриптом legacy в отдельном exec-канале (по `$SHELL`: обычный, fish или RouterOS), и записывается в хост. Autocomplete — встроенное автодополнение legacy («hydrogen»), без ИИ и подсказок путей: когда интеграция с оболочкой отметила приглашение, набранный текст сверяется с Shell History (сначала команды этого хоста) и однострочными сниппетами, под курсором показывается до 8 вариантов; ↑/↓ выбор, Tab или → вставляют выбранный (или первый), Enter запускает выбранный, Escape скрывает до следующего приглашения; после стрелок влево/вправо в строке, Tab оболочки и подобных клавиш подсказки прячутся до следующего приглашения; в разделённой вкладке, как в legacy, выключено; переключатель — Settings → Terminal → Autocomplete (включён). Проверено тестами модели и вручную в локальном zsh (подсказка и вставка по Tab). Import shell history читает существующую историю при новом подключении (см. ниже). Под Keyword highlighting, как в legacy, — «Would you like to add custom rules…» и кнопка «Let us know»; в legacy она ведёт на страницу отзывов Termius, которой в бандле нет, здесь открывает GitHub Issues проекта. **Shortcuts** — схемы legacy: «Mac hotkeys» (на macOS) и «PC hotkeys» с теми же сочетаниями, «Disabled», свои схемы. Щелчок по строке записывает новое сочетание (Enter — сохранить, Backspace — отключить действие, Escape — отмена; для переключения вкладок [1…9] и панелей — только модификаторы), занятое сочетание снимается с другого действия с предупреждением. Изменение встроенной схемы создаёт «<имя> copy»; свою схему можно переименовать и удалить с подтверждением. Сочетания действуют в главном окне сразу. Хранится на устройстве, как в legacy. Все действия схемы выполняются; Jump To открывает Command Palette. Проверено на демо-данных: запись ⌘⇧H для Open Hosts Page, создание копии схемы, ⌘2, ⌘⇧H, ⌘P, ⌘T, ⌘W в главном окне, удаление схемы. Проверено тестами моделей (тексты состояний, очистка логов, удаление логов в облаке на тестовом сервере, ассоциации) и вручную на демо-данных (`TERMIAN_DEMO=1`): открытие Settings из меню, все вкладки, смена темы, шрифта и размера в открытом терминале, форма «Своё облако» из Account. С живым сервером синхронизации и на Windows не проверялось.

**Import shell history** в Settings → Terminal (включён по умолчанию) при открытии локального Unix-терминала или после SSH-входа читает до 10 000 записей bash, zsh или fish в фоне, без выполнения команд истории и без их вывода в терминал или лог сессии. Для SSH используется отдельный exec-канал; при переподключении импорт повторяется без дубликатов и повышения рейтинга существующих команд. Новые записи добавляются после уже сохранённых, без выдуманной даты исполнения, с привязкой к сохранённому хосту; общий предел — 2000 команд. Они доступны в Shell History и автодополнении. Чтение ограничено 10 секундами и 4 МиБ вывода на запрос; ошибки, неподдерживаемая оболочка и слишком большой ответ пропускаются, не мешая терминалу. Используются стандартные `~/.bash_history`, `~/.zsh_history` и история fish `fish`; конфигурация оболочки не загружается намеренно (zsh всё же может прочитать системный или пользовательский `.zshenv`), собственные пути/сессии истории не подхватываются. Разбор построчный, как в legacy, без гарантии сохранения многострочных команд. Переключатель действует для новых подключений и переподключений; выключение также отбрасывает пришедший позже результат. Проверено на изолированных файлах настоящих bash, zsh и fish и на тестовом SSH-сервере, включая отключённый импорт, сохранность файлов и отсутствие выполнения команд; GUI, настоящий удалённый сервер и Windows не проверялись. Локальный импорт на Windows пока не реализован.

Автообновление нативного клиента читает тот же `latest.json` релиза и принимает только пакеты, подписанные публичным ключом из `assets/app/update-public-key` и привязанные к объявленной версии (`version:` в подписи). Проверка идёт через 20 секунд после запуска и затем каждые 6 часов; найденный пакет скачивается и встаёт на место `.app` (macOS, `darwin-aarch64`) или портативного EXE (Windows, `windows-x86_64`), а уведомление «Termian … установлен» предлагает «Перезапустить» или «Позже». Работает только в сборках с `TERMIAN_RELEASE_VERSION`; локальная сборка не обновляется, `TERMIAN_DISABLE_UPDATES` отключает проверку. Проверки подписи, разбора `latest.json` и замены бандла выполняются в тестах. В отличие от legacy, бандл без прав на запись не обновляется (legacy запрашивает пароль администратора). В Settings → Version выберите "Latest" для стабильных выпусков или "Pre-release" для бета-версий и нажмите "Проверить обновления". По умолчанию выбран "Latest". Канал сохраняется на устройстве; при смене канала клиент не устанавливает более старую версию. Для выпуска беты запустите workflow Release Termian вручную с версией вида `1.2.3-beta.1`.

SSH в нативном клиенте: при подключении вкладка показывает экран подключения, как в legacy-клиенте (шаги, отпечаток ключа, «Close / Continue / Add and continue», запрос пароля, «Show logs», «Retry»); тот же экран используется для SFTP. Ключи хостов хранятся в собственном `known_hosts` (`~/Library/Application Support/termian-native/known_hosts` на macOS): «Continue» доверяет ключу только на эту сессию, «Add and continue» сохраняет его; сменившийся ключ блокирует подключение. Аутентификация: ключи `~/.ssh/id_ed25519`, `id_ecdsa`, `id_rsa`, затем пароль или keyboard-interactive. Пароли и ключи из Vault legacy-клиента расшифровываются при импорте: хост с identity из Keychain получает её, собственные учётные данные хоста (скрытая identity legacy) переносятся в карточку хоста (скрытые identity, которые прежний импорт показал в Keychain, один раз возвращаются в хосты, а не используемые ни одним хостом удаляются из Keychain; identity, созданные в этом клиенте, не затрагиваются), ключи — с приватной частью и парольной фразой. Профиль, импортированный раньше без секретов, дополняется при следующем запуске: совпадение по id и имени, уже заданные здесь значения сохраняются; скрытые identity, попавшие в Keychain при старом импорте, один раз при запуске переносятся обратно в карточку хоста (только если свежее чтение legacy подтверждает, что это собственные данные того же хоста, с тем же id и именем) и удаляются из Keychain, когда на них больше не ссылается ни один хост; identity, созданные здесь, не трогаются. Перенос проверен тестом, на настоящем профиле не проверялся. Если какой-то секрет не расшифровывается, он пропускается, а «Отправить» и синхронизация остаются заблокированы, чтобы не стереть секреты в облаке. Пароль хоста или identity пробуется перед вопросом о пароле. Проверено тестами на синтетическом профиле; с настоящим профилем legacy и в GUI не проверялось.

Нативный клиент хранит данные в зашифрованном `vault.bin` в каталоге `termian-native`. На Mac с Secure Enclave пароль учётной записи macOS или Touch ID открывает Vault при каждом запуске, в том числе без сети. Если отменить запрос, Vault останется закрыт. Профиль legacy не меняется; существующий нативный Vault обновляется при первом успешном открытии ([ADR 0002](docs/adr/0002-native-vault-storage.md)). Пароль своего облака остаётся отдельным. `TERMIAN_DEMO=1` использует отдельный тестовый файл без системной аутентификации.

Профиль legacy-клиента читается только на чтение: базы IndexedDB копируются во временный каталог. Пока поддерживается только профиль WebKit на macOS; профиль WebView2 на Windows (LevelDB) не читается.

Первый запуск на macOS импортирует найденный старый профиль в свой Vault. На Windows старый WebView2-профиль не читается: перенесите данные через своё облако. Не удаляйте старые профили до проверки импорта. Если сохранился `legacy/dist/termian-data/`, это данные прежней портативной версии.

Кнопка с замком закрывает интерфейс поверх открытых сессий. Если пароль облака не задан и системная аутентификация macOS недоступна, первое нажатие предложит задать и повторить пароль блокировки для этого устройства. В остальных случаях подходит пароль облака или системная аутентификация macOS. При возвращении в заблокированное окно Termian предлагает Touch ID, если он настроен. Блокировка действует до закрытия приложения. Смена пароля облака начинается в [панели сервера](cloud-sync-server/README.md#change-the-encryption-password), затем новый пароль проверяется и сохраняется на клиентах.

`Tab` и `Shift+Tab` перемещают фокус по элементам окна. `Enter` или `Space` активирует выделенную кнопку. `Ctrl+Tab` и `Ctrl+Shift+Tab` переключают вкладки, `F6` возвращает фокус к панели вкладок. В активном терминале обычный `Tab` передаётся оболочке. В меню панели Vaults можно выбирать пункты стрелками и закрывать меню через `Esc`.

Страницы New Tab, SFTP, разделы Vaults, страницы настроек, диалоги, меню и уведомления плавно проявляются на месте. Активная вкладка выделяется фоном. Кнопки, вкладки, карточки и пункты меню подсвечиваются при наведении и меняют фон при нажатии. В списке Recent connections значки ОС отцентрированы на плашках с отступом от края. Правые редакторы выезжают сбоку и сдвигают список, а у переключателей двигается бегунок. Новые эффекты учитывают системную настройку уменьшения движения при запуске клиента.
